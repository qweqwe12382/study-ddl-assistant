## 已修复的问题

### 1. 部分历史记录显示时间提前 8 小时

实际观察：北京时间约 11:35 的计划调整回执在页面显示为 03:35。数据库读取的部分日期失去时区，响应返回无时区字符串，导致前端再次按本地时间解释。

增加统一的 `UtcDateTime` 响应类型，将持久化的 UTC 时间明确序列化为带时区时间，应用于任务、资料、计划、课程、课表、助手历史等只读响应。用户输入的本地截止和考试时间仍沿用原有转换规则，未修改数据库内容。

新增回归覆盖无时区 UTC、带时区 UTC、北京时间偏移、多个业务接口和助手回执。完整后端 300 项通过；重启隔离服务后，页面正确显示 11:35 的计划调整与 11:32 的完成记录。

### 2. 文件下载没有统一使用已登录请求配置

原先导出地址与普通接口分别计算 API 地址，在 `localhost` 与 `127.0.0.1` 混用时存在会话主机不一致风险；部分原件下载还会直接打开新窗口，失败时缺少清晰反馈。

所有下载入口改用同一 API 基址和共享的带会话 HTTP 客户端。收到文件后再触发保存；原件使用原始文件名，计划 Markdown 使用计划标题；失败时显示提示，不把错误响应当文件保存，也不额外打开空白窗口。

新增下载行为契约覆盖基址、请求方式、内容、中文文件名、保存链接、清理时机和失败分支。浏览器实际文件请求返回 200；原生保存结果的验收边界见上表。

### 3. 资料来源异常分支引用了不存在的函数

任务页的来源解析回退路径使用了未定义的 `plainObject`，在目标不可用时会抛出额外异常。改为直接检查返回的 `items`，保留原有身份校验和不可用提示。

相关静态检查、来源导航契约和后端身份保护测试通过。未通过浏览器人为制造“点击瞬间原实体被另一会话删除”的竞态，避免把自动化覆盖误称为完整人工复现。

### 4. 前端检查遗漏了 Vue 组件

原 ESLint 配置忽略 `.vue`，无法发现上面的未定义变量。现已纳入全部 36 个 Vue 组件，同时检查模板属性；修复查出的无效变量与组件默认值作用域问题。表单草稿只允许原有的嵌套字段更新，仍禁止替换父级属性。

完整前端 `verify` 已通过，后续同类遗漏可以在构建前发现。

### 5. 任务用时控件与反馈入口不够明确

为四个小时/分钟输入分别补充可访问名称，明确区分预计用时和剩余用时。任务已有实际用时或难度时，回执入口显示“查看或更新反馈”，减少用户以为尚未保存的误解。

浏览器确认保存后重新打开能读到 45 分钟、难度 4；未修改时不能重复保存。

## 页面呈现复核

保留并复核此前完成的深绿与墨色视觉体系、清晰标题层级、较克制的装饰和简洁视图。中文使用本地 Noto Sans SC 界面子集，西文与数字使用 Manrope；字体原始授权随项目保存，出处与维护方法见 [字体说明](../../frontend/public/fonts/README.md)。运行时字体不依赖第三方字体服务。

全部 11 个页面在桌面和手机测试尺寸下未出现整页横向溢出。手机资料库的默认简洁视图使用纵向卡片，添加、核对与查看入口可见；完整视图的宽表格仍存在下面记录的可用性改进空间。本轮并未进行完整 WCAG 或屏幕阅读器认证。
