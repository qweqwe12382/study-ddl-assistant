## 🧭 文档定位

本文档规定项目文档的唯一入口、状态口径、更新责任和发布前检查方式。README 是操作入口；[`docs/README.md`](../README.md) 是文档分组入口；项目目标文档是需求基线；比赛要求对照文档负责把官方要求映射到当前产品方向；`docs/product/`、`docs/quality/` 和 `docs/delivery/` 分别服务于产品架构、质量验证和交付准备。

比赛规则、赛道和命题编号以官方参赛手册为最高依据；附件模板用于组织提交格式。若手册与附件模板冲突，应记录冲突并向组委会确认，不能静默混用。当前已知冲突是 DDL 智能体在参赛手册中为中兴赛道命题四，在附件4中被写成命题三；项目统一按手册使用命题四。

当不同文档出现表述差异时，按以下优先级处理：

1. README 的“文档状态”和“当前里程碑”代表可运行版本的当前事实；
2. 比赛要求对照文档定义 M8 的智能体产品方向，但其中“计划新增”内容不代表已实现；
3. 正式测试用例的自动化基线代表最近一次可复现验证结果；
4. 开发进度记录实施过程，旧里程碑中的数字仅作为历史记录；
5. 项目目标文档保留需求与方案背景，已完成项应在当前文档中同步更新。

## 🏷️ 状态与版本口径

| 状态 | 含义 | 是否可作为当前承诺 |
| --- | --- | --- |
| 进行中 | 已进入开发或材料整理，但仍有明确待办 | 仅承诺已验证部分 |
| 已完成 | 功能或文档已实现，并通过对应验收 | 可以作为当前版本能力 |
| 基线文档 | 记录需求或历史方案，可能包含阶段性计划 | 以当前交付文档为准 |
| 已归档 | 仅保留历史记录，不再作为实施依据 | 不作为当前承诺 |

“当前状态入口”只汇总已经核验的比赛完成度，不替代 README、测试、架构或合规文档中的详细证据。

版本状态统一使用 `M0`—`M9` 里程碑：M8 为智能体能力增强，M9 为比赛材料与最终彩排。涉及数量、测试结果、依赖版本或界面行为的内容必须注明最后核对日期，避免把历史快照误读为当前状态。

## ✍️ 更新规则

1. 代码行为变化时，先更新 README 的操作说明，再更新受影响的架构、测试或合规文档。
2. 新增接口、环境变量或导出格式时，必须同时更新 README API 表、正式测试用例和相关演示步骤。
3. 任何外部 Provider、数据留存或隐私边界变化，都必须更新合规说明，并明确默认配置是否仍然安全。
4. 演示流程变化时，更新演示清单的时间表、备用路径和交付包，不在现场临时修改功能范围。
5. 历史阶段的测试数量可以保留，但必须使用“历史验证”或对应阶段标题，当前基线只写在 README 和正式测试用例中。
6. Markdown 链接优先使用仓库内相对路径；命令必须标注 `powershell`、`bash` 或其他实际 shell 类型。

## ✅ M9 发布前文档门禁

在提交、录屏或现场演示前，从项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
```

并逐项确认：

- [ ] README 的启动命令、端口和环境变量与脚本一致；
- [ ] 正式测试用例中的自动化基线与最近一次执行结果一致；
- [ ] 参赛赛道、命题编号、统一必测用例与官方手册一致，模板冲突已注明；
- [ ] 技术报告、评测用例实际结果、演示视频、报名信息和签字承诺书已齐；
- [ ] 架构图、数据边界和已知限制没有承诺当前版本之外的能力；
- [ ] 演示清单包含 iCal、移动端和失败备用路径；
- [ ] 合规说明未出现真实姓名、学号、手机号、API 密钥或私人文件；
- [ ] 所有交付文档链接可打开，标题层级和代码围栏完整；
- [ ] 工作区未把 `data/auth.db`、`data/app.db`、`data/users/`、上传原文件或含身份信息的日志打包提交。
