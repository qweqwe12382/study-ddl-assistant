# 离线备份与隔离恢复

适用范围：当前版本的本地 SQLite 实例。先停止前后端及其他写入进程；备份期间不上传、不修改数据。工具不会读取 `.env`，也不会自动寻找或覆盖个人数据库。它保存整个实例的账号和学习数据，不是单个账号的导出，也不是用于提交比赛的公开文件。

## 备份

确认运行实例实际使用的四个位置：`DATABASE_URL` 对应的 SQLite 文件、`AUTH_DATABASE_URL` 对应的 SQLite 文件、`USER_DATABASE_DIR`、`UPLOAD_DIR`。不要凭目录名称猜测；相对路径的解释还可能受启动目录影响。`USER_DATABASE_DIR` 默认保持原 `backend/data/users`；新版本支持显式绝对路径。

以下 PowerShell 命令从任意目录执行。输入实际绝对路径，输出目录必须尚不存在，且不能放进任一源目录。

```powershell
$projectRoot = 'C:\Users\28928\Desktop\GPT_work\huatai_proj'
$systemDb = Read-Host '系统业务 SQLite 文件的绝对路径'
$authDb = Read-Host '账号 SQLite 文件的绝对路径'
$userDbDir = Read-Host 'USER_DATABASE_DIR 的绝对路径'
$uploadsDir = Read-Host 'UPLOAD_DIR 的绝对路径'
$backupDir = Read-Host '新的备份目录绝对路径'
& "$projectRoot\.venv\Scripts\python.exe" "$projectRoot\scripts\backup_data.py" backup --system-db $systemDb --auth-db $authDb --user-dir $userDbDir --uploads $uploadsDir --output $backupDir --services-stopped
if ($LASTEXITCODE -ne 0) { throw '备份失败；不要使用该输出目录' }
& "$projectRoot\.venv\Scripts\python.exe" "$projectRoot\scripts\backup_data.py" verify $backupDir
```

`--services-stopped` 表示操作者已停服，并非工具自动停止了服务。多数据库与上传文件不能获得同一个 SQLite 事务快照；工具额外比较源文件集及数据库/WAL等文件摘要，发现变化会失败，但这不能替代停服。

备份目录包含数据库副本、上传文件和 `manifest.json`。清单记录文件 SHA-256、大小、应用模型代码指纹、数据库表结构摘要、逐表行数、账号映射和未引用文件。SQLite 副本使用 backup API，检查完整性及外键；资料引用核对实际文件与可用的数据库大小/哈希。旧记录缺少大小或哈希会单独计数，不能据此声称已与原始资料校验。未初始化账号、孤立数据库和未引用上传文件明确列出，保留原文件，不自动归属其他账号。

仅清空备份副本的登录会话并记录数量，账号密码哈希、管理员标记、用户工作区映射和业务数据保持原样。模型密钥、`.env` 和进程内教务登录状态不导出。备份包含账号邮箱、密码哈希及学习内容，须作为私人数据保管；SHA-256 用于检测文件变化，不是加密或来源签名。

## 恢复到新目录

使用创建备份时匹配的应用模型/迁移代码版本。模型指纹不同会拒绝恢复；此工具不做跨版本数据库升级。先验证备份，再恢复到不存在的目录：

```powershell
$restoreDir = Read-Host '新的恢复目录绝对路径'
& "$projectRoot\.venv\Scripts\python.exe" "$projectRoot\scripts\backup_data.py" restore $backupDir $restoreDir
if ($LASTEXITCODE -ne 0) { throw '恢复失败；不要启动该输出目录' }
& "$projectRoot\.venv\Scripts\python.exe" "$projectRoot\scripts\backup_data.py" verify $restoreDir
if ($LASTEXITCODE -ne 0) { throw '恢复目录校验未通过' }
$runtimePaths = Get-Content -LiteralPath "$restoreDir\runtime-paths.json" -Raw | ConvertFrom-Json
$runtimePaths.PSObject.Properties | ForEach-Object { [Environment]::SetEnvironmentVariable($_.Name, [string]$_.Value, 'Process') }
& "$projectRoot\scripts\start-dev.ps1"
```

启动前停止旧服务，避免启动脚本复用已占用端口的旧实例。四个数据路径必须一起设置，尤其不能只修改主业务库而漏掉用户库目录。登录账号保持不变，旧浏览器登录会话失效，需要重新登录。

恢复目录启动后会产生正常写入，此时不再是静态快照，原清单的哈希不应继续作为运行数据的校验值；如需新的快照，停服后重新备份到另一个目录。执行失败可能留下部分输出，必须保留错误信息排查，不将其视为可用备份或继续覆盖它。工具拒绝现有目标、目录穿越、链接/junction、修改过的备份、意外用户库文件和未完成 `.part` 文件。
